description: 只需确认一次的限价单、止盈、止损、追踪止损、定投和跟单，以及只通知你、不交易的提醒。
---

自动订单是你在卡片上确认一次的交易，之后每当条件满足，它就在卡片上的范围内自动成交。提醒只通知你，不发送任何链上交易。

:::caution[自动订单只在模拟模式下成交]
实盘自动订单的成交目前是关闭的。Agent 处于实盘时，binference 会拒绝自动订单，错误为 `order.live_fills_off`。请在 Agent 处于模拟模式时下自动订单，它们会以真实价格模拟成交。订单保持创建时的模式，因此 Agent 切换到实盘后，模拟订单仍按模拟成交。
:::

## 订单类型

| 类型     | 用途                                       |
| -------- | ------------------------------------------ |
| 限价单   | 价格达到触发价格时买入或卖出               |
| 止盈     | 价格涨到触发价格时卖出                     |
| 止损     | 价格跌到触发价格时卖出                     |
| 追踪止损 | 价格从订单开始后的最高点回落设定幅度时卖出 |
| 定投     | 按计划买入固定金额                         |
| 跟单     | 你关注的钱包买入或卖出时跟着买入或卖出     |

## 下单

在对话中告诉 Agent，例如“CAKE 跌到 $1.80 时止损”或“每周一 9 点买入 $20 的 BNB”。Agent 会提议这个订单，卡片列出每一项范围：代币、买入或卖出、数量、钱包、触发条件、最差价格、最大滑点和订单结束时间。确认这张卡片一次；之后每次成交都在这些范围内进行，无需卡片。MCP 客户端也可以用同样的方式提议订单，卡片同样等你确认。

以下情况下，binference 会在显示卡片之前拒绝订单：

- 要求的滑点超过 Agent 的限额（`order.slippage_limit`）
- 价格监控无法为代币定价（`order.unpriced_token`）：代币需要有发射台的联合曲线，或者有一个 WBNB 或稳定币交易额至少 $1,000 的 PancakeSwap 交易池
- Agent 处于实盘（`order.live_fills_off`）

Telegram 中的 `/orders` 列出生效中的订单及其触发条件和成交次数。要取消订单，告诉 Agent 即可；取消不需要卡片。

## 成交过程

价格监控在每个新区块读取每个有生效订单的代币的价格。触发条件满足时，binference 计算成交数量，按订单的范围和 Agent 的 24 小时上限检查，然后成交。每次成交限时 30 秒；超时的成交会被跳过。

- **最差价格。** 限价单和止盈默认以触发价格或更好的价格成交。止损和追踪止损没有最差价格，会在订单的滑点范围内按市价卖出。
- **成交次数。** 价格订单只成交一次，除非卡片写明更多次数。一次成交后，要等条件不再满足，它才能再次成交。
- **平仓订单一起结束。** 当一个平仓订单（止盈、止损、追踪止损或限价卖出）卖完整个持仓时，该持仓的其他平仓订单会结束，你会收到 [`ordersEnded`](/zh-cn/reference/notices/#ordersended) 通知。
- **到期。** 订单在 Agent 的订单有效期后结束，默认 30 天（`defaults.orders.expiryDays`），除非卡片写明更早的结束时间；要求更晚结束的订单会被拒绝。可用 `binference limit set orders.expiryDays=7` 修改。到期前一天你会收到 [`orderExpiring`](/zh-cn/reference/notices/#orderexpiring) 通知。
- **失败。** 连续 5 次成交失败后，订单会被取消，并发送 [`fillsFailing`](/zh-cn/reference/notices/#fillsfailing) 通知。

每次成交会发送 [`fill`](/zh-cn/reference/notices/#fill) 通知，每次跳过会发送带原因的 [`skipped`](/zh-cn/reference/notices/#skipped) 通知。两者都可以通过 `defaults.notifications.muted` 按 Agent 静音。

## 定投

定投订单只买入。它的计划写明分钟、小时、日期、月份和星期，默认使用你的时区，也可以指定其他时区，并可以在买入一定次数后停止。在计划时间后 60 秒内无法开始的买入会记为错过，以后也不会补买。

## 跟单

跟单订单跟随一个带单钱包，复制它对代币的买入和卖出。

- **买入。** 每笔跟单买入的金额取以下三者中最小的：订单自己的金额、Agent 的 `defaults.copy.perBuyUsd`（默认 $20），以及带单钱包实际花费的金额。低于 $5 的买入会被跳过，每个订单每小时最多买入 10 次。
- **每日上限。** 跟随同一个带单钱包每天最多花费 `defaults.copy.perLeaderDayUsd`（默认 $200），如果订单自己写明了每日上限，也受它限制。
- **卖出。** 带单钱包卖出其持仓的一部分时，订单会按相同比例卖出它买入的部分。因暂时原因失败的卖出会在一小时内每分钟重试一次。
- **延迟的交易。** binference 在带单钱包的交易达到 12 个区块深度后才读取。延迟超过 60 秒的买入永远不会执行。卖出即使延迟也会按当时的价格执行，通知会说明它是延迟的。
- 带单钱包不能是你自己的钱包，每个 Agent 最多关注 50 个钱包。

跟单订单的每次跳过都会发送通知：每个订单每小时最多 5 条，其余的由一条 [`copyHeld`](/zh-cn/reference/notices/#copyheld) 汇总。

## 冻结和停机

冻结会暂停每个生效中的订单；解除冻结后，订单恢复生效，如果已过期则变为已过期。仍在等待卡片的订单会被取消。

引擎停止后重新启动、机器休眠后恢复，或者时钟变动超过一分钟时，binference 会在任何订单成交前，用新的价格把每个订单检查一次。成交永远不会使用停止前读取的价格。检查过订单时，你会收到一条 [`resumed`](/zh-cn/reference/notices/#resumed) 通知，列出成交和跳过的情况。

## 提醒

提醒在某件事发生时通知你，从不交易，也不打开卡片。告诉 Agent 设置提醒，它会立即生效；要删除提醒，也告诉 Agent 即可。

- **价格提醒。** 代币达到某个价格。只触发一次。
- **钱包提醒。** 你关注的钱包进行交易。每笔交易都会触发。
- **发射提醒。** Flap、Genius.fun 或 Brew 上的新代币通过你的筛选条件，例如交易税、曲线进度、流动性、内部钱包数量或创建者的其他发射。每次匹配都会触发。

提醒还可以唤醒 Agent：它会开始 Agent 的一次回答，并标记为外部内容，每个 Agent 每小时最多 10 次。每个提醒每小时最多发送 5 条通知，其余的由一条 [`alertHeld`](/zh-cn/reference/notices/#alertheld) 汇总。每个 Agent 最多有 50 个生效中的提醒。钱包提醒和发射提醒默认在 30 天后结束。
