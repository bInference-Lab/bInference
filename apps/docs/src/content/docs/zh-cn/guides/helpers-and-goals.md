Agent 可以把一项边界清楚的任务交给助手，在多轮中推进一个目标，告诉你它自己的状态，并为自己编写技能。这些都不会确认卡片或修改限额：由它们引出的交易仍要等你点按确认，除非[自动模式](/zh-cn/guides/safety/#自动模式)允许。

## 助手

助手是在后台运行的一次模型调用，拥有自己的会话，开始时只有 Agent 写给它的任务说明，用来处理一项可以与对话并行的任务，例如同时调研几个代币。它使用 Agent 的读取工具、命令行工具和文件工具来读取、搜索并在机器上工作。它从不提议操作，不向你提问，也不启动自己的助手。它的报告会在之后的一轮中到达 Agent，Agent 据此回答你。Agent 启动或读取助手时你会看到一行进度，但永远看不到助手自己的对话。

- 每个 Agent 同时最多运行 4 个助手。
- 每次运行有 10 分钟，Agent 要求时可为 1 到 30 分钟。
- 助手使用 Agent 的主模型，除非 Agent 指定另一个已配置的模型；它花费的是 Agent 自己的模型预算。
- 读过外部内容的助手，其报告会像网页一样标记这个对话。
- 控制台中的“停止”、Telegram 或终端对话中的 `/stop`、冻结以及新对话，都会停止 Agent 的助手。binference 重启会结束正在运行的助手，Agent 会收到消息。

## Agent 的状态

`agent_status` 读取 Agent 自己的状态：模拟还是实盘、是否冻结、批准模式、正在使用的模型、今日模型花费与预算以及预算何时重置、这个对话的轮数和上下文的占用程度、这个对话是否读过外部内容、正在运行的助手、binference 的版本和当前时间。问 Agent 它的模型或预算时，它会据此回答。

让 Agent 在这个对话中换一个模型，它就会切换到一个写成 `<provider>/<model>` 的模型，该服务商必须在 `models.providers` 中配置过。切换会保持到对话被清空，不修改任何配置项，也不需要卡片；每日模型预算仍会限制它的花费。Telegram 中的 `/ai` 则用于选择 Agent 的主模型。

## 目标

目标是 Agent 一轮接一轮持续推进、直到完成的任务。在 Telegram 或终端对话中用 `/goal` 加上 Agent 要达成的目标来设置，或者让 Agent 替你设置：

```text
/goal 检查我持有的每个代币是否有卖出税，并把结果写入 taxes.md
```

每一轮结束后，等对话空闲下来，binference 就会开始下一个目标轮。你的消息总是优先。目标轮和其他轮一样：由它引出的交易需要你的卡片确认，除非自动模式允许，所有限额照常适用。

| 命令                | 用途                                     |
| ------------------- | ---------------------------------------- |
| `/goal`             | 显示目标、它的目标轮和花费，以及进度说明 |
| `/goal <objective>` | 设置目标                                 |
| `/goal pause`       | 暂停目标                                 |
| `/goal resume`      | 恢复目标                                 |
| `/goal clear`       | 清除目标                                 |

控制台在对话上方显示目标，并提供“暂停目标”“恢复目标”和“清除目标”按钮。

每个对话只有一个目标，新对话会忘记它。Agent 确认整个目标都已完成后会把它标记为完成；同一个阻碍连续 3 个目标轮都出现时会把它标记为受阻。目标在以下情况下会暂停，并显示一条说明原因的状态行：

- 你停止了 Agent，或 Agent 被冻结
- 当天的模型预算用完，或目标自己的预算用完（只有你为目标指定了美元金额时，Agent 才会设置这个预算）
- 进行了 50 个目标轮之后；`/goal resume` 会再给它 50 个
- 连续 3 个目标轮没有进展之后

没有调用任何工具的目标轮，会等一分钟再开始下一个。Agent 只在你要求时设置目标，并且从不在读过外部内容的对话中设置，所以网页无法给它设定目标。

### 进度说明

Agent 会在目标旁保留一份简短的进度说明：一段状态和最多 12 个步骤的计划，每个步骤为已完成、进行中或待完成。Telegram 把它保存在一条原地编辑的消息中；控制台在对话旁显示它；终端对话在它变化时打印出来。

## Agent 编写的技能

Agent 可以提出一个新技能，或对它某个工作区技能的修改。技能提案从不会自行应用：你阅读后再应用或拒绝。提案会显示 Agent 写的一行原因、具体修改和扫描结果；只要有任何扫描结果，在 Agent 修订之前就无法应用。读过外部内容的对话不会提出任何提案，Agent 也不能应用、拒绝或删除提案。

- 在 Telegram 中，`/skills` 显示每个提案，并附有“应用”和“拒绝”按钮。
- 在控制台中，技能页面显示每个提案及其修改；点按“应用”时会再确认一次。
- 在终端中：`binference skill proposals`、`binference skill show <proposal>`、`binference skill apply <proposal>` 和 `binference skill reject <proposal> --reason <text>`。

Agent 会在下一轮得知你的决定，拒绝时还会得知你的理由。手动或通过命令添加、修改的工作区技能，会等你接受后才生效：`/skills` 中会显示它并附有“接受”按钮，控制台的技能页面也会显示它，在终端中则用 `binference skill accept <name>` 接受。[插件、技能和 MCP](/zh-cn/guides/plugins-and-skills/#agent-提议的技能) 说明扫描会检查哪些内容。
