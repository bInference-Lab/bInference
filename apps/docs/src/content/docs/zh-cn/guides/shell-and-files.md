你的 Agent 可以在运行 binference 的机器上工作：用命令行工具运行命令，用文件工具读取和修改文件。两者都以你自己的系统用户身份运行，所以能访问你能访问的一切，只有 binference 自己的文件夹除外。它们都不能确认卡片、修改限额或接触密钥。

## 隔离墙

binference 的状态文件夹（默认为 `~/.binference`）中保存着密钥、数据库、`config.json5`、命令行的访问令牌和引擎的套接字。Agent 的命令和文件工具永远不能读取或修改其中的任何内容，只有其中的 `workspace/` 文件夹对 Agent 开放。指向该文件夹的链接同样过不去：每个路径都按其真实路径读取，每次文件调用只使用它检查过的那个文件。

- 在 macOS 上，Seatbelt 规则集把每条命令隔离开。命令也无法访问钥匙串。
- 在 Linux 上，bubblewrap 把每条命令隔离开。请安装 `bwrap`；没有它，每条命令都会被拒绝，并附上说明原因的消息。
- Windows 还没有隔离墙，所以在 Windows 上 Agent 的命令行工具是关闭的。

命令从不会在没有隔离墙的情况下运行。你的用户拥有的其他一切仍在它的范围内：你的其他文件，以及网络。保护你资金的仍是[安全指南](/zh-cn/guides/safety/)中的卡片、限额和上限。

## 命令行工具

`shell` 在你的登录 shell 中运行一行命令，Agent 读取它的输出（标准输出和标准错误合在一起）以及退出码。除非 Agent 指定其他文件夹，命令从你的主文件夹开始运行。它不读取 shell 的任何启动文件（例如 `.zshrc`），所以其中的别名和 `PATH` 设置不生效。它得到 binference 启动时的环境变量，但去掉了 binference 自己的变量，以及 `config.json5` 中每个密钥来源读取的变量。命令不读取任何输入，所以 Agent 会把每个回答都放进参数里。

Agent 最多等待 20 秒让命令结束，除非它要求更久，否则等 10 秒。到时仍在运行的命令会作为命令任务继续运行，由 `shell_job` 读取或停止；服务器或耗时的构建可以直接作为命令任务启动。命令会在 `shell.timeoutSeconds`（默认 1,800 秒）后停止，除非 Agent 指定其他时限；0 表示不限时。命令任务在命令结束后保留 30 分钟，binference 重启后不会保留任何命令任务。

Agent 留在后台运行的命令任务结束时，Agent 会收到一条消息：退出码、运行时长和最后 20 行输出。以退出码 0 结束且没有新输出的命令任务不会通知 Agent，除非 `shell.tellOnQuietEnd` 为 `true`。控制台中的“停止”、Telegram 或终端对话中的 `/stop`，以及冻结，都会停止 Agent 运行的每条命令。

## 先问你的命令

三个配置项决定哪些命令可以运行：

| 配置项             | 决定什么                                                                                           | 默认值   |
| ------------------ | -------------------------------------------------------------------------------------------------- | -------- |
| `shell.run`        | `any` 运行任何命令；`listed` 只运行你始终允许的命令；`off` 不运行任何命令                          | `any`    |
| `shell.ask`        | `never` 从不询问；`unlisted` 对每条你没有始终允许的命令询问；`always` 对每条命令询问               | `never`  |
| `shell.onNoAnswer` | 你 10 分钟没有回复的请求如何处理：`refuse` 什么都不运行；`listed` 只在届时已允许时运行；`any` 运行 | `refuse` |

默认情况下，每条命令都会立即运行。当 `shell.ask` 为 `unlisted` 或 `always` 时，命令会等待你的回复：“允许一次”“始终允许”或“拒绝”。等待期间 Agent 的这一轮会结束，你的回复会以命令的结果开始它的下一轮。每个 Agent 同一时间只有一个未处理的命令请求；新的请求会取代旧的，旧的永远不会运行。

在任何界面都可以回复命令请求：

- 在 Telegram 中，它出现在你的私聊里，附带这三个按钮。
- 在控制台中，它显示在消息框上方。
- 在终端对话中，按 1 允许一次，按 2 始终允许，按 3 拒绝；不提供“始终允许”时，按 1 允许一次，按 2 拒绝。
- 在命令行中，`binference shell requests` 列出请求，`binference shell allow <request>` 允许运行一次，加上 `--always` 会把它保存为允许的命令，`binference shell refuse <request>` 拒绝它。

最先的回复生效。10 分钟后由 `shell.onNoAnswer` 决定，但不会超过 `shell.run` 允许的范围。

### 允许的命令

“始终允许”会把命令行中的每一步保存为一条允许的命令：程序的真实路径、逐字相同的每个参数，以及它开始运行的文件夹。在某个文件夹中允许的 `git status` 只覆盖那里的这条命令，不包括 `git push`，也不包括其他文件夹。由 `|`、`&&` 或 `;` 连接的多步命令行，只有每一步都被允许时才算允许。

有些命令行 binference 无法完整判断，在 `unlisted` 下总会询问：带变量、重定向、通配符、命令替换、子 shell、`if` 或 `for` 的命令行，以及 `eval`、`source` 或 `cd` 这类步骤。它们不提供“始终允许”；运行其他代码的步骤也不提供，例如 `bash`、`python`、`node`、`env`、`sudo`、`xargs`、`find`、`make` 或 `npx`。

`binference shell allowed list` 显示允许的命令，`binference shell allowed remove <allowed>` 撤回其中一条。每次变化都会以 [`shellAllowed`](/zh-cn/reference/notices/#shellallowed) 或 [`shellDisallowed`](/zh-cn/reference/notices/#shelldisallowed) 通知告诉你。

允许的命令绑定的是它的字面内容，而不是程序读取的内容。如果程序读取 Agent 可以写入的文件，例如代码仓库的 `.git/config` 或主文件夹中某个工具的设置，它会按那个文件的内容行事。询问你是对 Agent 所运行命令的检查；保护 binference 的密钥和你的资金的，仍是隔离墙、卡片和上限。

## Agent 读回的内容

命令输出的一切都是外部内容：任何程序、文件或网页都能把文字放进去。Agent 读取后，这个对话会像读过网页一样被标记，之后的卡片会带有警告，自动模式会在每张卡片上询问你，直到你发送 `/clear`。

在 Agent 读取输出之前，binference 会隐藏 PEM 格式的私钥和 12 个词以上的助记词。以十六进制写出的裸私钥会保留，因为交易哈希看起来一样。

## 文件工具

| 工具         | 用途                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| `file_read`  | 按页读取文本文件，每页最多 2,000 行或 10 KB，并说明下一页从哪里开始；图片文件则改为描述 |
| `file_write` | 整体写入一个文件，并创建所需的文件夹                                                    |
| `file_edit`  | 在一个文件中替换确切的文字                                                              |
| `file_patch` | 用一个补丁修改多个文件；只要有一处修改找不到，就什么都不写                              |

路径可以是绝对路径、以 `~/` 开头表示你的主文件夹，或相对于工作区文件夹。每个文件最多读写 10 MiB。写入时先在旁边写一个新文件再替换原文件，并保留其权限。编辑会精确查找要替换的文字，或用宽松匹配查找（忽略行尾空格，并把弯引号和破折号当作普通字符）；无论哪种方式，这段文字都必须只出现一次。PDF 改由 `read_pdf` 读取，见[图片指南](/zh-cn/guides/media-and-screen/#图片和-pdf)。

两个配置项决定文件工具能访问哪里：

- `files.workspaceOnly`，默认 `false`：`true` 会把读取、写入和编辑限制在工作区文件夹内。
- `files.patchWorkspaceOnly`，默认 `true`：补丁只修改工作区文件夹中的文件；`false` 允许补丁修改 binference 自己的文件夹之外的任何文件。

文件工具会拒绝：

- binference 自己的文件夹中的路径，工作区除外
- 配置项限制在工作区内时，工作区文件夹之外的路径
- 在工作区技能文件夹中写入或删除：Agent 只能通过你应用的[技能提案](/zh-cn/guides/helpers-and-goals/#agent-编写的技能)修改自己的技能
- 在 binference 检查时指向了另一个文件的路径，例如恰好在那一刻被移动的链接：不会读取、写入或删除任何内容，Agent 会重新读取这个路径
- 文件夹、非文本文件，以及超过 10 MiB 的文件

`file_read` 显示的内容同样是外部内容，并且原样显示：写在文件中的密钥会不加隐藏地到达 Agent。
